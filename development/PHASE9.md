# Phase 9: CSV/XLSX import and Excel export

## Desktop behavior inspected

- `ProfilingLists` accepts `.csv` and `.xlsx`. Both readers expect `SIN`, `FullName`, `BusinessName`, `BusinessSection`, `StallNumber`, `StallSize`, `MonthlyRental`, `PaymentStatus`, `StartDate`, `Penalty`, `AdditionalCharge`. SIN is supplied by the file. The desktop pre-check skips empty SIN/name and duplicate SIN, parses bad monetary values as zero, and then calls `Database.ImportProfiling`. That method validates required text and decimals, normalizes bad dates to empty, forces `IsArchived=0`, and uses `SqlBulkCopy`. It does not write audit rows or create bills/payments. A bulk-copy failure can obscure which row failed.
- `VehiclePermitLists` accepts `.csv` and `.xlsx`. CSV reads `CompanyName`, `DriverName`, `PlateNo`, `SECRegNo`, `DTINumber` by header; XLSX reads the first five columns by position. It skips empty and duplicate plates, generates `VIN-YYYY-NNNN` using an unprotected maximum, and calls `Database.ImportVehiclePermits` with `SqlBulkCopy`. Database validation requires VIN, company, and plate. Import does not set permit status/year, create permit history, fee drafts, OR numbers, or audit rows. The database enforces unique plate numbers. No vehicle restore caller or import audit call was found.
- Both desktop exports use ClosedXML `.xlsx`, copying the current active grid, so search/filter results are exported and archived rows are excluded. Profile column order: SIN, Full Name, Business Name, Business Section, Stall Number, Stall Size, Monthly Rental, Payment Status, Penalty, Additional Charge, Date of Occupancy. Vehicle order: VIN, Company Name, Driver Name, Plate No, SEC Reg No, DTI Number, Permit Status, Permit Year, Date Added. The web export keeps those useful columns and ordering.

## Web implementation

- [Profile transfer page](../BusinessPermitLicensingSystem.Web/Pages/Profiles/Transfer.cshtml) and [vehicle transfer page](../BusinessPermitLicensingSystem.Web/Pages/Vehicles/Transfer.cshtml) use authenticated browser uploads. Razor Pages validates anti-forgery tokens. Both imports accept `.csv` and `.xlsx` up to 5 MB, inspect the file header/signature, require the desktop field names, and process in memory. No uploaded filename becomes a filesystem path. ClosedXML 0.105.0 and CsvHelper 33.1.0 match the desktop package versions.
- Profile import retains supplied SIN and forces an active record. Required fields, length, name/stall format, section, positive stall size for non-flat rates, nonnegative two-decimal money, status, and occupancy date are validated. Blank penalty/additional charge become zero. Imported rental and `Paid` status are retained as desktop import allowed; this differs from web individual creation, which calculates rental and does not create Paid profiles. A Paid import creates no payment history, so it must be treated as a legacy status rather than proof of collection. Bad dates are rejected instead of silently erased.
- Vehicle import accepts only the five desktop source fields. Extra permit status/year columns are ignored; the database defaults remain Unpaid/year 0. A VIN is allocated inside a serializable transaction using SQL Server update and range locks. The unique plate and VIN constraints are the final duplicate safeguard. No existing VIN is rewritten.
- Rows are independent. A successful profile insert is one atomic SQL statement. A successful vehicle VIN allocation and insert commit in one transaction. Invalid, duplicate, skipped empty, and failed rows are counted and shown with source row numbers and safe reasons. One row does not roll back other imported rows. Bulk imports create no audit entries, matching desktop behavior. Phase 8 vehicle restore remains intentionally audited as approved.
- Exports query all active rows matching the requested desktop-style search, without list pagination. The resulting workbook has the desktop title, header order, and row values. Archived records are excluded. ClosedXML writes user text as string cell values; tests reopen the workbook and confirm a leading `=` remains text with no formula. Numeric amounts and permit year remain numeric cells.
- The service checks both Initial Catalog and the connected database name for `BPLS_Dev`. No schema migration, production connection, background job, or WinForms edit was made.

## Known differences and proposed next phase

- Web imports reject invalid dates, bad money, missing headers, and invalid profile formats with row reasons. Desktop import could silently coerce some of these or fail the whole bulk copy. Web vehicle XLSX uses named headers rather than only fixed positions to prevent field shifts.
- Imported profile `Paid` and supplied rental remain policy-sensitive legacy behavior. They create no billing or payment transactions. Phase 7 fee-draft and separate OR-number policies remain unchanged.
- Proposed Phase 10 scope: read-only monthly and collection reports, followed by print/download output matching the desktop report columns and date rules. Confirm exact report set and layout before implementation. No Phase 10 work has begun.
